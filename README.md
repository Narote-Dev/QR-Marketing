# Build Your QR — Phase 3.5 Templates

This repository contains the Phase 3.5 foundation for Build Your QR: client-side static QR generation, curated SEO pages, visual templates, local preset assets, and composite PNG download. Authentication, analytics, dynamic QR codes, payments, and persistence are not included yet.

## Structure

```text
frontend/                 Next.js, TypeScript, Tailwind CSS, shadcn/ui setup
  lib/templates/          Template types, catalog, apply helpers
  lib/assets/             Local preset asset registry
  public/presets/         Demo logos, icons, backgrounds, thumbnails, previews
  app/templates/          Curated template SEO routes
backend/QrMarketing.Api/  ASP.NET Core 8 API, EF Core, PostgreSQL provider
database/                 PostgreSQL bootstrap location and notes
docker-compose.yml        Full local stack
```

## Prerequisites

- Node.js 20+
- .NET SDK 8+
- Docker Desktop

## Local run

Copy `.env.example` to `.env`, then start PostgreSQL:

```powershell
docker compose up -d database
```

Run the API:

```powershell
dotnet restore .\backend\QrMarketing.Api\QrMarketing.Api.csproj
dotnet run --project .\backend\QrMarketing.Api\QrMarketing.Api.csproj --urls http://localhost:8080
```

In a second terminal, copy `frontend/.env.local.example` to `frontend/.env.local`, then run:

```powershell
npm install --prefix .\frontend
npm run dev --prefix .\frontend
```

Open http://localhost:3000 to use the static QR generator.

## Static QR generator

The frontend provides immediate, client-side QR previews for URL, text, WiFi, email, phone, and SMS content. QR payload construction and validation live in `frontend/lib/qr/content.ts`; reusable generator UI components live in `frontend/components/`. The designer supports colors, dot and eye styles, uploaded or preset logos, logo size, gradient, correction level, QR size, optional frames, and preset backgrounds. Nothing is sent to or saved by the API.

## Template and preset system (Phase 3.5)

Users can pick a curated visual template before entering QR content. Selecting a template applies colors, dot/eye styles, frame, frame text, optional logo, and optional background image through `applyTemplate()` without changing the QR payload pipeline.

### Template data structure

Each template in `frontend/lib/templates/catalog.ts` includes:

- `id`, `name`, `slug`, `category`, `description`
- `thumbnail`, `previewImage`
- `defaultForegroundColor`, `defaultBackgroundColor`
- `defaultDotStyle`, `defaultEyeStyle`
- `defaultFrame`, `defaultFrameText`
- optional `logo`, optional `backgroundImage`

Asset metadata lives in `frontend/lib/assets/catalog.ts` under categories `logos`, `icons`, `backgrounds`, and `template-thumbnails`.

### Add a new template

1. Add any new SVG/PNG files under `frontend/public/presets/...`.
2. Register the files in `frontend/lib/assets/catalog.ts` if they are reusable assets.
3. Append a `QrTemplate` object to `templates` in `frontend/lib/templates/catalog.ts`.
4. Keep categories unique with a new `slug` inside the category.
5. Run `npm test --prefix .\frontend`.

### Replace a demo image asset

1. Overwrite the matching file under `frontend/public/presets/{logos|icons|backgrounds|thumbnails|previews}/`.
2. Keep the same filename if the catalog path should stay unchanged.
3. Or add a new file, update the path in `frontend/lib/assets/catalog.ts` / template catalog, then retest.

### Composite download

The preview download button exports a PNG that composites the QR code with the selected background, frame, and frame text. Export runs entirely in the browser.

## SEO foundation

Curated, indexable public pages are available at `/qr-code-generator` and `/qr-code/url`, `/qr-code/wifi`, `/qr-code/email`, `/qr-code/phone`, and `/qr-code/sms`. Template SEO pages are also curated at `/templates` plus `/templates/restaurant`, `/templates/cafe`, `/templates/hotel`, `/templates/menu`, and `/templates/wifi`. Each has unique metadata, a canonical URL, Open Graph and Twitter cards, WebApplication/FAQ/Breadcrumb JSON-LD, helpful how-to content, FAQs, and related internal links. `sitemap.xml` and `robots.txt` are generated by Next.js.

Set `NEXT_PUBLIC_SITE_URL` to the production HTTPS origin before deployment so canonical URLs, Open Graph URLs, sitemap entries, and JSON-LD use your live domain:

```powershell
$env:NEXT_PUBLIC_SITE_URL = 'https://your-domain.example'
```

## Google AdSense architecture

Ads are disabled by default and no placeholder or fake ads are rendered. The QR creator itself remains ad-free. When explicitly enabled, available placements are: below an SEO landing-page tool, an optional desktop-only SEO sidebar, between future blog article sections, and at a future blog article’s bottom.

Set these values in the frontend deployment environment at build time:

```powershell
$env:NEXT_PUBLIC_ENABLE_ADSENSE = 'true'
$env:NEXT_PUBLIC_ADSENSE_PUBLISHER_ID = 'ca-pub-your-publisher-id'
$env:NEXT_PUBLIC_ADSENSE_SLOT_SEO_AFTER_TOOL = 'your-slot-id'
```

Add the other placement slot IDs only when those placements are approved for use. To disable ads in development, leave `NEXT_PUBLIC_ENABLE_ADSENSE=false` (the default) or omit the publisher ID. The AdSense client script is not included and no ad containers are rendered unless both are configured.

`ads.txt` is generated at `/ads.txt` from the configured publisher ID, so it stays consistent with the ad script. When AdSense is not configured it returns an empty file.

## Google Analytics and consent

GA4 and a consent banner follow the same opt-in pattern. Set `NEXT_PUBLIC_ENABLE_ANALYTICS=true` plus `NEXT_PUBLIC_GA_MEASUREMENT_ID` to load Google Analytics 4. Set `NEXT_PUBLIC_ENABLE_CONSENT=true` to activate Google Consent Mode v2 defaults plus a three-language consent banner.

When consent is enabled, ad and analytics storage are denied by default and only updated after the visitor accepts. The AdSlot component also waits for advertising consent before requesting an ad. For full EU/UK personalized-ads compliance, replace the built-in banner with a Google-certified CMP that supports the TCF v2.0 framework.

## Database configuration

Compose passes the connection through `ConnectionStrings__DefaultConnection`. For local API execution, override the development placeholder with an environment variable:

```powershell
$env:ConnectionStrings__DefaultConnection = 'Host=localhost;Port=5432;Database=qrmarketing;Username=qrmarketing;Password=your-local-password'
```

`Cors__AllowedOrigins` configures permitted frontend origins; `NEXT_PUBLIC_API_BASE_URL` configures the browser API URL.

## Architecture

The frontend and backend are independently deployable. Controllers only handle HTTP concerns: `PlatformController` delegates to a DI-registered service, which accesses EF Core through `QrMarketingDbContext`. Configuration is environment based, and committed credentials are local-development placeholders only.

## Known limitations

- No migrations or tables exist yet because no persistent domain model has been introduced.
- Template demo assets are local placeholders, not production brand photography.
- Only six template SEO routes are published; remaining categories stay available inside the generator UI.
- Docker Desktop is required to run PostgreSQL locally.
